# 🎟️ nf-raffle

> [!TIP]
> **[Click here for instructions on how to enter the raffle](https://seqeralabs.github.io/nf-raffle/)**

This repository contains code for the nf-raffle pipeline, which is used for managing raffles at events attended or sponsored by Seqera.

## Description

nf-raffle is a Nextflow pipeline that enters you into an event raffle. It submits your details to the event's Google Form and writes a raffle ticket (`raffle_ticket.html`) to the output directory.

## Supported Events

Pass one of these to `--event`. Running without `--event` enters the default event.

Any other `--event` value fails before anything is submitted. Configs for past events are kept in [`event_configs/archive/`](event_configs/archive/) and can't be selected.

## How to Run

There are two ways to run the raffle:

* From Seqera Platform at the booth. Come talk to us!
* From the Nextflow command line on your laptop (see below)

If you are already familiar with Nextflow:

```bash
nextflow run seqeralabs/nf-raffle --email EMAIL --event EVENT \
  --first_name FIRST --last_name LAST --affiliation ORGANIZATION
```

Connecting the run to Seqera Platform (`-with-tower`, or `nextflow auth login`) earns extra raffle entries. Run `nextflow run seqeralabs/nf-raffle --help` to list all parameters.

Below are detailed instructions for new users.

### Step 1: Install Nextflow

This pipeline requires Nextflow 26.10.0 or later. First, ensure you have Java 17 or later installed, then install Nextflow:

```bash
# Install Nextflow
curl -s https://get.nextflow.io | bash

# Make it executable and move to your PATH
chmod +x nextflow
sudo mv nextflow /usr/local/bin/
```

Verify the installation:

```bash
nextflow -version
```

Check that the reported version is 26.10.0 or later. Older versions stop with a version error before the pipeline starts. Run `nextflow self-update` to upgrade.

### Step 2: Create a Seqera Platform Account (optional, for extra entries)

1. Visit [https://cloud.seqera.io](https://cloud.seqera.io)
2. Sign up for a free account or sign in with your existing credentials
3. Complete the account verification process

### Step 3: Generate an Access Token

1. Navigate to **Your profile** → **Access tokens** in the Seqera Platform
2. Click **New token**
3. Provide a name for your token (e.g., "nf-raffle-token")
4. Click **Create** and copy the generated token

### Step 4: Set Environment Variable

```bash
export TOWER_ACCESS_TOKEN=your_token_here
```

### Step 5: Run the Pipeline

```bash
nextflow run seqeralabs/nf-raffle --email EMAIL --event EVENT \
  --first_name FIRST --last_name LAST --affiliation ORGANIZATION -with-tower
```

Leave out `--event` to enter the default event. `--first_name`, `--last_name` and `--affiliation` are only required for events that list them in the table above; the pipeline tells you if one is missing.

## Parameters

| Parameter | Default | Description |
| --- | --- | --- |
| `--email` | (required) | Your email address |
| `--event` | `ashg_2026` | Event to enter, see [Supported Events](#supported-events) |
| `--first_name` | `""` | First name; required by some events |
| `--last_name` | `""` | Last name; required by some events |
| `--affiliation` | `""` | Company or institution; required by some events |
| `--outdir` | `results` | Where `raffle_ticket.html` is written |

Parameters are validated against [`nextflow_schema.json`](nextflow_schema.json) with the [nf-schema](https://github.com/nextflow-io/nf-schema) plugin when the run starts.

## What gets submitted

Besides the details you provide, each entry includes some run context that the event's form may ask for. Every value is sent only if the event's config maps it to a form question (`form_fields` in `event_configs/<event>.json`) and the value is not empty; anything else is skipped.

| Field | Value |
| --- | --- |
| `email`, `first_name`, `last_name`, `affiliation` | Your parameters |
| `run_name` | The Nextflow run name (also your ticket number) |
| `uuid` | A random ID generated for the entry |
| `platform_enabled` | `true` if Seqera Platform monitoring is on (extra entries) |
| `hostname` | Hostname of the machine that ran the entry |
| `user_name` | System user name running the pipeline |
| `workspace_id` | Seqera Platform workspace ID (`TOWER_WORKSPACE_ID`), if any |
| `platform_workflow_id` | Seqera Platform workflow ID (`TOWER_WORKFLOW_ID`), set when launched from Platform |

`hostname`, `user_name`, `workspace_id` and `platform_workflow_id` help the organizers tell booth demo runs by Seqera staff apart from participant entries.

## For maintainers

* [Adding a new event](docs/ADDING_AN_EVENT.md): Google Form setup checklist and `scripts/new_event.py`.
* Testing: `nextflow run . -profile test` posts to a local mock form instead of a real one. Start the mock first with `python3 tests/mock_form_server.py --port 8765 --log requests.jsonl`. CI ([`.github/workflows/run-pipeline.yml`](.github/workflows/run-pipeline.yml)) does this, runs `nextflow lint`, validates every event config, and checks the generated ticket. It never submits to a real event form.
